# Contributing

Thanks for taking part in the Pharaonic community. Answering a question, sharing what you learned, and marking the answer that worked all help the next developer with the same problem.

## Choosing the Right Place

Use [discussions](https://github.com/orgs/Pharaonic/discussions) when something is still a question or an open idea. Use the package's own repository when the work is concrete:

- **Bug you can reproduce:** open an issue in that package's repository.
- **Specific feature for one package:** open a feature request in that package's repository.
- **Not sure if it's a bug, or how something should work:** start in Q&A.
- **New package, or an idea that spans packages:** start in Ideas.
- **Security vulnerability:** report it privately as described in [SECURITY.md](SECURITY.md).

## Asking a Good Question

A question that can be reproduced gets answered faster. Include:

- the package and version, plus your PHP and framework versions;
- a minimal code sample, as text rather than a screenshot;
- what you expected, what happened instead, and the full error message;
- what you have already tried.

When a reply solves your problem, mark it as the answer so others can find it. If you solve it yourself, post the solution.

## Proposing an Idea

Start with the problem, not the API. Explain what you are trying to do, why the current options fall short, and what you considered. Pharaonic packages stay small and focused, so an idea may fit better as a separate package, or may be left to application code.

An idea that gets agreement moves to the relevant repository as an issue. A positive discussion is not a commitment to build it.

## Helping Others

- Answer the question that was asked, and explain why your answer works.
- Say so when you are unsure, or when your answer depends on a specific version.
- Disclose your connection to any product you recommend.
- Keep replies on topic. Use reactions instead of "+1" comments.

## Changing This Repository

Pull requests are welcome for this repository's documentation, discussion forms, and labels. Keep each pull request to one focused change. Package changes belong in that package's repository.

## Conduct

Every discussion follows the [Code of Conduct](CODE_OF_CONDUCT.md).
